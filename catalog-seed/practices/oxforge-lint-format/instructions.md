Use the shared Oxforge base or recommended configuration, version 0.2.0 or later. Add framework presets as needed; keep local overrides small and explained. Do not copy anti-slop plugin scripts into consuming repositories. Keep consistent-return and prefer-readonly-parameter-types off as defined by shared policy.

The semantic check follows bounded repository-local JSON/JSONC inheritance. It accepts exact, caret and tilde declarations with a supported lower bound. Unresolved catalogs/workspaces, dynamic TypeScript configs, cycles, unread files and multiple entry points require review rather than being labelled missing.

This is a configuration-inheritance check, not proof that CI executes the linter or that every local override is appropriate. Explicitly exclude approved native/framework/vendor exceptions with appliesTo.exclude and record the reason here; do not erase their native tooling to make a generic check green. For monorepos use a separate check with directory set to the package root, or the shared root where policy is declared.

Use the `oxforge-format` check instead of comparing `oxfmt.config.ts` to a catalog copy. It accepts the shared `format-config` and `format-tailwind` exports, static object spreads and project overrides, and the `format()` helper from `@aranlucas/oxforge/format`. When `tailwindcss` appears in dependencies, devDependencies, optionalDependencies or peerDependencies, the exported config must enable `sortTailwindcss`. The version declaration does not need to be resolved to establish that Tailwind is used.

For Tailwind projects, keep project-specific stylesheet paths. Either import `base` from `@aranlucas/oxforge/format-tailwind` and export `{ ...base, sortTailwindcss: { ...base.sortTailwindcss, stylesheet: "app/globals.css" } }`, or use `format({ sortTailwindcss: { stylesheet: "app/globals.css" } })`. Adapt the stylesheet path to the project; it is not required to match the catalog. Projects without Tailwind may continue re-exporting `@aranlucas/oxforge/format-config`.

The formatter check interprets a bounded subset of static syntax in `oxfmt.config.ts` without importing repository code. Type-only imports and variable type annotations are accepted; preserve them when adapting project configs. Dynamic configs, other TypeScript constructs and unsupported wrappers require review. For monorepos set `directory` to the package root. Preserve diagnostic and domain/security test scripts unless independently proven unused.
